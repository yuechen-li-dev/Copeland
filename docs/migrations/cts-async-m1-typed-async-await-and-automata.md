# CTS-ASYNC-M1 typed async/await and automata migration record

**Status:** complete as the bounded explicit-state-machine slice. CTS-ASYNC-M2 continues the unsupported expression families and source forms listed below.

The first implementation increment adds the compiler-local MIR contract required for a single shared lowering: `MirAsyncType`, `MirAsyncCallableType`, `MirSuspensionAutomaton`, deterministic explicit state/frame identities, typed suspension/resume/cancellation/completion transitions, bounded resource defaults, and shared malformed-automaton validation. It also adds initial named-function frontend support: `async function`, `Async<T>`, and typed `await`; `await operation?` parses as `(await operation)?`. The lowerer now creates a validated skeleton for every async function, including parameter/local frame slots and one suspension state per structured-MIR await. It additionally splits supported statements into `MirAsyncExecutionPlan` states before target emission, with the authoritative frame-slot ID recorded on direct await states.

The validator is intentionally backend-neutral. It prevents either backend from receiving an automaton with an unknown edge, duplicate identity, invalid entry, non-Async await operand, incompatible resume/completion type, invalid cancellation target, dead nonterminal state, unreachable generated state, or a breached state/transition/suspension/slot/worklist bound. Focused tests prove a valid machine and representative malformed cases.

The first executable vertical slice now realizes named async functions in C#, Diagnostic JavaScript, and Symbolic JavaScript. Each emitted call allocates a compiler-owned `Async` carrier and frame, starts a deterministic `switch`-based step routine eagerly, retains local/pending values in that frame, and subscribes to the carrier rather than using host `async`/`await`, Task faults, or Promise rejection. Completed carriers retain their value for repeated observation. The shared plan emits branches, loops, loop jumps, awaits, expression evaluations, and Result propagation through explicit states. Await-bearing arithmetic, calls, assignments, returns, conditional expressions, logical short-circuiting, and `try` value blocks now resume through compiler-owned carrier/result slots. A propagated Result error either resolves the function's declared Result or writes the typed payload to a retained handler slot and jumps to the validated lexical `except` state. This is intentionally bounded: match/result/table/TSON expression transfer, source-level cancellation delivery, async arrows/captures/generics/associated functions, and an externally completable source operation still require the general lowering.

The runtime now also supplies an internal pending-computation factory for test and future sidecar use. Its carrier arbitrates resolve, cancel, and panic as distinct exactly-once terminal states; late terminal attempts are ignored and cancellation continuations prevent success resumption. It is not a Copeland source feature and has no Task/Promise or sidecar transport semantics.

The slice deliberately does not emit C# `async`, JavaScript `async function`, generators, Promise/Task source interop, sidecar transport, or a user cancellation API. CTS-ASYNC-M2 will extend the same compiler-owned plan with enum/Result match dispatch, remaining expression families, callable source forms, and broader evidence; it is implementation continuation, not a replacement architecture.
