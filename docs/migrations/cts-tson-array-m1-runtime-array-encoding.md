# CTS-TSON-ARRAY-M1 runtime array encoding

**Outcome:** complete and closed. CTS-TSON-ARRAY-M1 extends the existing runtime canonical encoder with structural `MirTsonArrayPlan` nodes and shared validation. It keeps one nominal record or payload-enum root, supports only Boolean, Number, String, Record, Enum, and nested array elements, and retains the existing two-case `TsonEncodeError` model.

Generated C# and JavaScript use direct indexed traversal over ordinary mutable `T[]` and JavaScript arrays. Each entry captures the receiver and length once, checks the shared 100,000-element ceiling before traversal, and reads indices once in ascending order. Empty arrays retain plan schema evidence. Canonical schema text remains ordinary `T[]`; canonical values retain M0b multiline array formatting.

The checked-in ARRAY-M1 corpus at `tests/Copeland/Copeland.TS.Tests/TsonEncoding/Corpus/arrays` pins source, authoring asset, canonical runtime text, MIR, C#, and JavaScript UTF-8 bytes/SHA-256. `Array_corpus_has_two_generation_csharp_node_fixed_point_and_pinned_artifacts` proves authored asset → generated C#/Node canonical text → canonical reader/printer fixed point, then fresh in-memory canonical asset → generated C#/Node byte-identical text. It also proves no asset path or authoring comments remain in MIR, emitted artifacts, or runtime text. `Array_runtime_carriers_have_exact_boundaries_and_javascript_terminal_invariants` adds the runtime 99,999/100,000/100,001 boundary exercise, sparse/non-array carrier rejection, and exactly-once JavaScript indexed observation. The reader's exact array, depth, and value-node boundaries remain covered by `TsonFeatureTests`.

`TsonArray` is immutable compiler-host semantic data. Generated C# `T[]` and JavaScript arrays are private ordinary mutable runtime carriers. `tsonEncode` observes the carrier state at call time; aliasing, identity, and mutation history do not enter canonical TSON, which remains a finite immutable tree. The runtime has no parser, filesystem, compiler-host TSON dependency, JSON, reflection, `dynamic`, property enumeration, root arrays, TSON Results/tables/optionals/interfaces/aliases, package change, commit, push, or publication. The complete ledger and pinned inventory are in [the ARRAY-M1 architecture record](../Copeland/architecture/copeland-ts-runtime-tson-array-encoding-cts-tson-array-m1.md#requirement-ledger).
