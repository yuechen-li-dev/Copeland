# Aurelian Claude hardening cross-check — M22

Claude's review is treated here as an adversarial bug report, not as design authority. The supplied review contained seven numbered findings; `PlantKind` was a qualification attached to finding 7.

| Finding | Confirmed? | Evidence | Action | Owner |
| --- | --- | --- | --- | --- |
| `AurelianFrameLoop` retained every iteration until return | Confirmed | The original `RunAsync` appended every `AurelianFrameLoopIterationResult` to one unbounded `List<>`. The preserved 100k harness semantics retained 100,000 records and had a post-warmup live-memory slope of about 335 bytes/frame. | `RunAsync` now retains no iterations; `RunHarnessAsync` explicitly captures a finite full transcript; `RunWithSinkAsync` streams to caller-owned policy. | `Aurelian.Core.Engine.Frames` |
| Async frame execution plus `ConfigureAwait(false)` had no explicit realtime/affinity decision | Partially confirmed | The older loop has up to four awaits and intentionally does not capture a synchronization context. The 1m completed-task control stayed on one thread, but that does not prove affinity under genuinely asynchronous completion. TinyFarm's shipping path is instead the synchronous `AurelianGameHost.RunFrame` and its Vulkan 100k trace records one thread. | Keep `ConfigureAwait(false)` for the context-free evidence loop; document that thread-affine native hosts own a synchronous pump. Do not build a second scheduler. | `Aurelian.Core`; `Aurelian.GameHost` |
| Compiler-shaped results allocate in realtime paths | Confirmed | The null control allocated about 6.7 KB/frame even after transcript removal. Native renderer counters attribute allocation across projection, composition, world/overlay preparation, native passes, and swapchain presentation. The dominant issue is allocation churn, not retained growth. | Removed transcript and unbounded loop-diagnostic retention. Preserve rich public results; defer a measured prepared-frame/scratch redesign rather than introduce unsafe pools in M22. | Runtime/render subsystem owners |
| Duplicate severity enums caused translation glue | Confirmed | Core frame, loop, runtime-step, engine, prepared-graphics, world-actuation, and plant-registry severities were identical. | Added dependency-free `Aurelian.Diagnostics` with shared `AurelianDiagnosticSeverity`; subsystem codes and diagnostic records remain typed. Runtime-tick mapping remains only for code/message ownership, not severity conversion. | `Aurelian.Diagnostics` |
| One-type-per-file fragmentation harmed locality | Confirmed in touched areas | Before M22 the checkout had 53 C# files in `Aurelian.Core` and 58 in `Rendering.Contracts`. Frame-loop execution required opening many tiny contract files. | Consolidated loop contracts into `FrameLoopContracts.cs` and runtime-tick contracts into `RuntimeTickContracts.cs`. Current Core count is 43 files. Rendering.Contracts is measured and documented but not churned without a touched semantic cluster. | `Aurelian.Core` |
| Names redundantly repeat namespace context | Confirmed, but broad rename rejected | `AurelianRuntimeTickFrameStepDiagnosticSeverity` was especially redundant. A repository-wide public rename would create churn unrelated to runtime hardening. | The egregious severity names were deleted through consolidation. Existing frame/result names remain for compatibility. New policy is namespace hierarchy plus local semantic identity. | Touched owners |
| `PlantRegistry` had dead `skipValidation` and an inconsistent `Single` path | Confirmed | The private constructor ignored `skipValidation`; it called `Single` after a separate validation path. | Removed the flag. Both public construction and `Create` now produce a validated state before selecting the presentation plant; stable AGP codes remain. | `Aurelian.Graphics.Plants` |
| `PlantKind { Unknown, Vulkan }` was an unproven multi-backend guess | Partially confirmed | The A23 provenance defines plant as an explicit native graphics device/ownership identity. Raster and Null are renderer mechanisms and do not own Vulkan device/queue resources, so adding them would conflate concepts. | Keep `Unknown` and `Vulkan`; document the single production plant family and do not add speculative cases. | `Aurelian.Graphics.Plants` |

The review's broader statement that Aurelian had “no shipping game loop” does not survive current source inspection. `Aurelian.GameHost` is a bounded synchronous native host and TinyFarm uses it directly. The ambiguity was real specifically in the older class named `AurelianFrameLoop`, whose `RunAsync` mixed production naming with harness retention.
