# Copeland TS 0.1.0 Preview 1 scope

> Keep TypeScript. Gain .NET.

The Preview 1 proof is deliberately bounded:

- Windows x64;
- .NET 10;
- one normal `.slnx` and SDK-style `.csproj`;
- Copeland `.ts` and authored `.cs` in one project;
- `tsconfig.tsx` as the ownership and orchestration authority;
- one specifically contracted real npm package;
- .NET BCL use and an authored C# type;
- packaged `Copeland.TS.Tool`, `Copeland.TS.Sdk`, and VS Code VSIX;
- normal `dotnet restore`, `dotnet build`, and `dotnet run`.

The user message is: **Write TypeScript and C# together in one .NET project.**
Traditional TypeScript remains owned by tsc. Copeland-owned TypeScript remains
owned by tscl. `tsconfig.tsx` makes that boundary explicit.

Preview 1 defers `tsconfig.json`, drop-in tsc compatibility, arbitrary Node
backend compatibility, Express/NestJS/Fastify, NativeAOT, Visual Studio,
Linux/macOS packaging proof, TSPack/browser workflows, frontend frameworks,
new language features, and marketplace publication.

## Release validation boundary

`Copeland.Release.slnx` is the source-controlled Preview 1 release product
closure. It contains the package roots (`Copeland.TS.Tool`, `Copeland.TS.Sdk`,
and `Copeland.TS.Templates`), their direct product dependencies, and the
release-authoritative compiler, backend, workspace, language-server, MSBuild,
and CLI tests. `tools/Test-CopelandReleaseClosure.ps1` verifies that the full
project-reference closure of each NuGet package root remains in that solution.

The protected release workflow deliberately excludes `tsxml-react-m0` and
`standalone-web-m0`. The React host is a browser integration fixture with
development-only wiring: `Host/Program.cs` consumes
`Copeland.Generated.Bridge`, but its host project has neither a project
reference nor a target that produces that generated C# source. This is a stale
sample/missing sample-generation-step defect, not a packaged compiler or SDK
dependency regression. The standalone host explicitly requires a local TSPack
executable. These samples remain prerequisite-aware development/integration
validation work, and TSPack is not part of the Preview 1 NuGet/npm/VSIX release
product closure. A successful release run means **Preview release product
closure validated**, not every Copeland sample validated.
