# Copeland TS language profile

> **Suspension and sidecar routing:** [CTS-AUTOMATA-M0a](../architecture/copeland-ts-suspension-automata-design-cts-automata-m0a.md) establishes a compiler-owned resumable-control lowering before async, sidecar calls, or iterators. [CTS-SIDECAR-M0a](copeland-ts-sidecar-interop-design-cts-sidecar-m0a.md) defines CLR-to-JavaScript communication as separate runtime partitions plus explicit generated TSON transport, not shared objects. Both are documentation-only: no `sidecar`, async, iterator, module, or browser-host source surface exists yet.

**Status:** canonical implemented product-language profile through CTS-CLASS-M1, closed CTS-TSON-TABLE-M3, CTS-CF-M0, and CTS-TYPE-M3. Immutable nominal records, pure classes, and immutable record tables are implemented through private C# and JavaScript realizations. TSON includes a dedicated nominal table root, shared-parser authoring/canonical reading, fixed-point printing, declaration-owned initialization, and demand-created authored-singleton runtime table encoding. Record-table data is columnar by law; canonical output and future default JSON compatibility are declaration-ordered objects of column arrays, never row-object arrays. [CTS-TYPE-M3](../architecture/copeland-ts-foundational-type-system-closeout-cts-type-m3.md) is the canonical authority for transparent non-generic aliases, erased field-only requirements, named closed generic functions, and local exact direct-argument inference. Interfaces and open generics remain frontend-only and never reach MIR or either backend. [CTS-CLASS-M1](../architecture/copeland-ts-pure-classes-cts-class-m1.md) adds controlled immutable nominal records with pure construction, associated functions, and privacy boundaries. [CTS-JS-EMIT-M0b](../architecture/copeland-ts-structured-javascript-emission-cts-js-emit-m0b.md) supplies the backend-local scoped binding/token-writer foundation; [CTS-JS-EMIT-M1](../architecture/copeland-ts-symbolic-javascript-emission-cts-js-emit-m1.md) adds an explicit executable Symbolic profile while Diagnostic remains default and artifact authority. Release remains unimplemented. Runtime decoding remains deferred until one parser architecture exists on both backends. JSON/serialization remains unimplemented and must be a compatibility lowering from TSON.

## Position

> Copeland TS is intended to be a TypeScript-shaped, closed-world language that preserves TypeScript’s authoring ergonomics without inheriting JavaScript’s dynamic runtime semantics.

“TypeScript-shaped” means that TypeScript 7 is the intended syntax and ecosystem reference point, not a promise of full TypeScript 7, JavaScript, npm, DOM, or arbitrary JavaScript-interop compatibility. Copeland TS owns its runtime meaning. JavaScript is the planned first usable distribution/reference backend; the C# backend is currently a proof backend and the later .NET direction is RyuJIT for ordinary managed execution, NativeAOT for supported native deployment, and .NET WebAssembly AOT for browser/Wasm. [CTS-TABLE-M0a](copeland-ts-record-tables-design-cts-table-m0a.md) is the accepted record-table design, implemented and closed through CTS-TABLE-M3. [CTS-TSON-TABLE-M0a](copeland-ts-tson-tables-design-cts-tson-table-m0a.md) remains the design authority and [CTS-TSON-TABLE-M0b](../architecture/copeland-ts-tson-table-semantic-model-cts-tson-table-m0b.md) implements its compiler-host semantic/canonical slice.

## Reading this profile

The status vocabulary is deliberate: **Normative direction**, **Implemented**, **Partially implemented**, **Intended, unimplemented**, **Historical experiment**, **Rejected**, and **Unresolved**. “Implemented” requires current production code and tests; a backend artifact alone does not establish a language law. Filesystem fixtures under `tests/Copeland/Copeland.TS.Tests/Language` establish frontend-to-MIR acceptance or deliberate validation rejection. [CTS-REC-M0a](copeland-ts-immutable-records-design-cts-rec-m0a.md) records the accepted record design, [CTS-REC-M0b](../architecture/copeland-ts-record-frontend-and-mir-cts-rec-m0b.md) records the implemented MIR boundary, and [CTS-REC-M3](../architecture/copeland-ts-immutable-records-closeout-cts-rec-m3.md) is the final ratification.

## Current implementation boundary

The implemented path is source text -> syntax -> binder -> Cope MIR -> deterministic `.cope` text, C# proof emission, or JavaScript emission. Transparent aliases are resolved and erased inside the frontend before that MIR boundary. The CLI accepts `compile <source> --emit mir|csharp|javascript`; valid tables and alias-authored programs reach every output. `.cope` is an expected textual projection of MIR, not source input or a parser contract. Backend representations remain implementation evidence rather than source-law authority.

## Explicit exclusions and planned work

Current exclusions include `var`, `===`, `!==`, `eval`, `null`, general object literals/dynamic member access, ternary `?:`, optional chaining `?.`, and implicit global assignment. Contextual record braces and statically resolved record fields are the only object-shaped operations admitted. The language also excludes truthiness, implicit coercion, `any`, ordinary `undefined`, ambient nullability, prototype behavior, and implicit host access.

## Unresolved decision surface

CTS-REC-M0b implements immutable nominal records through MIR without weakening the rejection of general objects; CTS-REC-M1 realizes them in C#, CTS-REC-M2 realizes them in JavaScript, and CTS-REC-M3 closes cross-backend stress, diagnostics, doctrine, and artifact stability. Record equality, patterns, serialization, interop, and recursive types remain deferred. **CTS-TABLE-M0b** implements the separately scoped table frontend-to-validated-MIR contract, **CTS-TABLE-M1** realizes canonical tables in C#, **CTS-TABLE-M2** realizes them in JavaScript, and **CTS-TABLE-M3** closes the core ladder. [CTS-TSON-M0a](copeland-ts-tson-design-cts-tson-m0a.md) owns the native typed-data laws, M0b implements the compiler-host parser/model/printer foundation, [CTS-TSON-M1a](copeland-ts-tson-value-projection-design-cts-tson-m1a.md) selects compile-time nominal asset ingestion rather than runtime decoding, [CTS-TSON-M1b](../architecture/copeland-ts-compile-time-tson-assets-cts-tson-m1b.md) implements that ingestion, and M2b/M2c implement and close reflection-free canonical encoding. [CTS-TSON-ARRAY-M0b](../architecture/copeland-ts-tson-arrays-and-assets-cts-tson-array-m0b.md) completes homogeneous typed-array semantic values and compile-time asset lowering, and [CTS-TSON-ARRAY-M1](../architecture/copeland-ts-runtime-tson-array-encoding-cts-tson-array-m1.md) closes runtime array encoding. [CTS-TSON-TABLE-M0b](../architecture/copeland-ts-tson-table-semantic-model-cts-tson-table-m0b.md) implements the dedicated nominal table root, bounded cell algebra, fixtures, and canonical fixed point selected by M0a; M1/M2 compiler and runtime integration remain deferred. JSON, including `JSON.stringify` of private JavaScript carriers, is unsupported and unimplemented; future table JSON follows nominal TSON table semantics and a policy-directed TSON-to-JSON compatibility lowering. ## CTS-M0b fixture contract

`TestData/Corpus` remains compiler-regression and generated-artifact evidence. `Language` is curated language-law evidence:

```text
tests/Copeland/Copeland.TS.Tests/Language/
  Valid/<semantic-area>/*.cl-valid.ts
  Invalid/<semantic-area>/*.cl-invalid.ts
```

- A valid fixture must parse, bind, validate, and lower to Cope MIR without diagnostics.
- An invalid fixture must be rejected by the intended language-validation stage. A crash, parser accident, backend failure, or unrelated diagnostic is not a correct rejection.
- Add exact diagnostic expectations only when diagnostic identity is itself contractual; add runtime companions only for observable execution semantics.
- No test DSL is needed merely to classify a source file as valid or invalid.

The fixture suite includes bounded M1b interface/generic acceptance and rejection coverage alongside aliases, records, tables, Results, control flow, and TSON. `var` and strict equality remain deliberate profile rejections; explicit optionality remains unresolved.
